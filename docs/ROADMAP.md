# 남극캠퍼스.ai 스터디룸 — 구현 로드맵

> 서비스명: **남극캠퍼스.ai** (2026-11-28, 이전 이름 "남극AI빌리지")

랜딩(`~/Developer/landing/adelie_landing`)에서 들어온 사용자가 남극 배경의 가상 스터디룸에 펭귄으로 입장해,
선생·학생 펭귄이 함께 공부하는 모습과 출석 현황을 실시간으로 보고, 말풍선·비밀 대화로 소통하는 공간.

## 기술 구성 (로컬 우선)

- **앱**: Next.js 16 (App Router) + TypeScript + Tailwind v4
- **인증 (마지막 단계)**: Auth.js + Google provider. 그 전까지는 임시 입장 폼
- **DB**: Drizzle ORM. 로컬에서는 SQLite로 시작하고, 운영 전환 시 Postgres로 교체
- **실시간**: Socket.IO 별도 Node 서버(`realtime/server.ts`, 포트 3001). 접속·위치·말풍선·비밀 대화 이벤트 처리
- **렌더링**: 2D 탑다운 빙하 맵. DOM과 SVG 펭귄(`src/components/penguin/Penguin.tsx`)으로 그림

## Firebase 전환 (2026-11-25 결정)

Socket.IO 서버(`realtime/`)를 없애고 Firebase로 옮깁니다. 웹은 Firebase App Hosting에 올리고, 랜딩(Vercel `adelie-ai`)에서 버튼으로 연결합니다.

| 기능 | 옮길 곳 |
|---|---|
| 로그인 | Firebase Auth (Google) |
| 프로필·접속·위치·자리·출석·말풍선·비밀 대화 | Realtime Database (asia-southeast1). 위치 전송은 초당 15번 → 5번으로 줄임 (전송량이 접속자 수의 제곱으로 늘어 비용에 직결) |
| 비밀 대화·신고·퇴장·역할 | Realtime Database + Cloud Functions(신고 스냅샷). Firestore는 쓰지 않아 전부 잠가 둠 |

로그인은 원래 마지막 단계였지만, 보안 규칙이 "누구인지"를 기준으로 동작하므로 F1으로 앞당겼습니다.

```bash
npm run dev          # Next(3000) + Firebase 에뮬레이터 (Auth·Realtime Database·Firestore·Storage·Functions, 관리 화면 4000)
npm run test:rules   # Realtime Database 보안 규칙 검증

npm run test:library # 📚 자료실 Firestore · Storage 규칙 검증 (dev 에뮬레이터를 끄고 실행)
```

에뮬레이터에서는 Google 대신 가짜 계정 선택 창이 떠요. 로컬 데이터는 `.data/emulators`에 남아요(Java 필요).

관리자로 테스트하려면 에뮬레이터 관리 화면 → Realtime Database에서 `users/{uid}/role`을 `"admin"`으로 바꾸고 다시 입장해요.
